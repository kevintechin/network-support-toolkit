# 網路健檢工具 1.2.8 — 使用手冊

**寫給執行檢測的人。** 按兩下、視窗自己跑完、把報告交給 IT，就這三件事。

本手冊對應繁體中文套件（`zh-TW` 資料夾）。`en-US` 資料夾裡的英文套件是同一支工具，附有英文版手冊。IT 人員的部署手冊就在旁邊（`NetworkHealthCheck_IT_Deployment_Manual_zh-TW.html`），設計、判定規則與驗證記錄在技術文件。

---

## 1 · 這個工具是什麼

網路健檢工具站在這台電腦的角度看網路，把看到的記下來：哪些網卡已連線、它們的位址是什麼、路由器（*預設閘道*）有沒有回應、名稱查得到查不到、幾個已知的服務連不連得上、連線有沒有掉封包或重傳資料。結果是一份報告，最上面是一行整體結果，再來是一段「**要告訴 IT 的話**」。

**它不改任何設定。** 工具只讀取網路資訊並執行連線測試：幾次 Ping、一次名稱查詢、一次 TCP 連線、一次 HTTPS 請求。它不會修改 IP、DNS、路由、防火牆、Proxy 或網卡設定，也不安裝任何東西。一般情況下不需要系統管理員權限。

**它不會上傳任何東西。** 以出廠設定來說，報告寫在這台電腦的資料夾裡，除非你自己送出，否則哪裡都不去；IT 可能把報告資料夾指到別處，報告的「電腦與執行資訊」一節會寫出實際位置。這台電腦上的資料夾，也可能是 Windows 會同步到雲端的資料夾：新的 Windows 11 預設把桌面和文件備份到 OneDrive，套件解壓縮在那裡的話，每份報告一寫出就會被複製上雲端；那是 Windows 做的，不是工具做的，第 5 節說明怎麼看出來、可以怎麼處理。測試送出的是往測試目標的流量（第 9 節列出出廠的目標），經由這台電腦自己的 DNS 伺服器、Proxy 與路由。

**要多久。** 以出廠設定、網路正常時大約十秒。有東西不回應時會久一些，出廠設定下最多兩分鐘上下，因為每項測試都會等到時限才放棄，而計數器讀取用完時限時還會再試一次才真的放棄：效能計數器完全不回應的電腦上，光是這些讀取就占了其中約八十秒。IT 若改了取樣秒數、目標或時限，執行時間會相應變長；進度列上方那一行會寫出目前的步驟，接近結束時還會倒數剩餘的取樣秒數，還在動的檢測就不是卡住。

## 2 · 開始之前

1. **把 ZIP 存到電腦上。** IT 給你的檔案，或是從他們給的連結下載的檔案，先存檔。不要直接從瀏覽器的下載列開啟。
2. **可以的話先解除封鎖。** 在 ZIP 上按右鍵 → **內容** → 勾選最下方的 **解除封鎖** → **確定**。Windows 會標記從網際網路下載的檔案，執行前先問一次安全性問題；解壓縮前先解除封鎖，就不會再問。沒有這個核取方塊，表示沒有東西需要解除，直接往下做。
3. **整包解壓縮。** 在 ZIP 上按右鍵 → **解壓縮全部…** → **解壓縮**（不同 Windows 版本的字樣略有不同）。Windows 會建議一個和 ZIP 同名的資料夾，用它就可以。放在本機任何位置都行，例如桌面或文件；不過新的 Windows 11 預設把這兩個位置備份到 OneDrive，寫在程式旁邊的報告也會跟著被複製上雲端（第 5 節）。
4. **資料夾要整包保留。** 啟動器需要程式和設定檔在旁邊。要搬或複製就搬整個資料夾，不要只拿單一檔案。

> **不要在 ZIP 視窗裡直接執行。** 對 ZIP 按兩下會把內容顯示得像資料夾，但它不是資料夾：Windows 只會把你按的那一個檔案解到暫存位置。啟動器在旁邊找不到東西就停下來：`Start-Traditional-Chinese.cmd` 說「找不到 zh-TW 繁體中文套件」，`zh-TW` 資料夾裡的 `Start-NetworkCheck.cmd` 則說「找不到程式檔 NetworkHealthCheck.ps1」。先解壓縮。

## 3 · 執行檢測

1. 打開解壓縮出來的資料夾，按兩下 **`Start-Traditional-Chinese.cmd`**。ZIP 裡面本來就帶一層資料夾，所以解壓縮出來的資料夾裡常常只有一樣東西：另一個同名的資料夾；進去，啟動器就在裡面。多一層、資料夾叫什麼名字，都沒有關係，只要整棵樹保持在一起。（進入 `zh-TW` 資料夾按兩下 `Start-NetworkCheck.cmd` 也是同一件事。）
2. 若 Windows 顯示 **開啟檔案 - 安全性警告**，選 **執行**。那是上一節說的下載標記，工具本身沒有差別。同一個對話框還會說無法確認發行者，發行者那一行寫著「發行者不明」：那是實情，這支工具沒有數位簽章。IT 手上代替簽章的是雜湊值：他們拿收到的 ZIP 的 SHA-256 和發行說明公布的那一個比對（IT 部署手冊第 6 節）。套件裡的 `SHA256SUMS.txt` 是另一種檢查：它證明套件裡的檔案彼此相符，證明不了套件是從哪裡來的。ZIP 是 IT 給你的，就選 **執行**；不確定檔案從哪裡來，先問過再執行。**開啟這個檔案前一定要先詢問** 保持勾選，代價是每次執行多按一下；取消勾選是把 Windows 對這一個檔案的標記永久移除，也就是第 2 節對整個 ZIP 做的解除封鎖，一次一個檔案。
3. 先出現一個黑色文字視窗，檢測結束前它會一直留在背景。不用理它。
4. 接著 **網路健檢工具 1.2.8** 視窗打開，一秒內**自己開始**。你會看到：

   | 畫面上 | 意思 |
   |---|---|
   | **結果：檢測進行中** | 正在檢測 |
   | 進度列和它上方那一行 | 目前進行的步驟，接近結束時會有幾秒顯示 *TCP 重傳取樣中，尚餘約 N 秒* |
   | 記錄區 | 每個步驟、每個發現各一行，依發生順序排列 |
   | 按鈕 | 檢測中 **開始檢測** 是灰的；**開啟報告**、**開啟報告資料夾**、**開啟 JSON** 要等做完才會亮起；在那之前 **關閉** 沒有作用 |

5. **等它做完。** 進度列上方那一行變成 **檢測完成**，結果那一行用顏色顯示整體結果，記錄區最後一行寫出報告位置：*報告已產生：…*。按鈕下方會寫出要交出去的那一個檔案：*把這個檔案交給 IT：…*，**開始檢測** 則變成 **重新檢測**。
6. 按 **開啟報告**。報告會在瀏覽器裡打開。它是這台電腦上的檔案，不是網際網路上的網頁。

**在問題發生的時候跑。** 工具量的是一台電腦的一個瞬間。問題如果時好時壞，一切正常時跑的那一次證明不了什麼，問題發生時跑的那一次才是 IT 需要的證據。跑的時候照平常的方式繼續使用網路：有幾秒鐘它在量這台電腦自己的流量，什麼都不做的電腦就沒有東西可量。

**再跑一次。** **重新檢測** 會在同一個視窗裡開始新的一輪。每一輪都寫出一組新的報告檔，檔名帶自己的時間，所以先前的報告不會被覆蓋，前提是一次只跑一份工具：兩份工具共用報告資料夾又在同一秒內結束，檔名會相同。一份好的時候、一份壞的時候，兩份報告對 IT 的價值高於任何一份單獨的。

## 4 · 看懂結果

### 整體結果

視窗裡的結果那一行，以及報告最上方的彩色方塊，會顯示四種整體結果之一：

| 整體結果 | 工具的說明 | 對你的意思 |
|---|---|---|
| **整體正常** | 本次可執行的必要檢查均通過。 | 這一刻所有能執行的必要檢查都通過。選用目標本身不計入：沒有回應的選用或額外 Ping、TCP、HTTP 目標會列在「資訊」列，那幾列也要看。兩個例外：IT 把選用目標編進必要連線群組時（出廠的 Internet 群組就是 TCP 與 HTTPS 測試），成員全部失敗，群組就失敗、整體結果跟著變成偵測到異常；解析不出來的選用 DNS 名稱則是「需注意」，會讓整體結果變成需要注意。問題如果還在，多半在檢測碰不到的地方，例如應用程式或伺服器，或者它時好時壞：問題發生時再跑一次。 |
| **需要注意** | 沒有必要項目失敗，但有警告或品質異常。 | 有連上線，但有些地方不對勁：封包遺失、延遲偏高、重傳、網卡錯誤，或其他警告。把報告送出。 |
| **偵測到異常** | 至少一項必要檢查未通過。 | 檢測要求的某個項目壞了。報告會寫出是哪一項、看到了什麼。把報告送出。 |
| **檢測未完整** | 部分檢查因權限、系統元件或執行錯誤而無法完成。 | 工具在這台電腦上有東西量不到。這不是網路故障的證明，也不是你做錯了什麼。把報告原樣送出。 |


**結果由什麼決定。** 整體結果跟著這次執行**量到**的東西走。量不到的統計、對所套用規則來說太小的樣本，以及關於「這次執行拿到什麼」的事實——打錯的目標、無法檢測的設定項目——都保有自己的列、徽章與統計數字，也會在摘要裡被點名，但不改變結果。凡是真的量到的都算，包含選用目標：回應不良的選用目標是一次量測。反過來說：結果回答的是「這台電腦的網路怎麼樣」，不是「框裡打了什麼字」。
### 要告訴 IT 的話

整體結果下面有一段「**要告訴 IT 的話**」：一個標題加兩到四行。**先讀這一段**，它是工具自己對問題在哪裡的判讀，是寫給你看的；最後一行永遠會提醒你該送哪個檔、裡面有什麼。

| 標題 | 內容 |
|---|---|
| **全部通過** | 本次執行的所有必要檢查都通過 —— 若有選用目標沒有回應，下一行會點名它，並說明這不影響整體結果。若問題仍然存在，可能在應用程式或伺服器端，或是時好時壞；問題發生時再跑一次。 |
| **本機連線問題** | 找不到可用的網卡或預設閘道。問題在這台電腦或它的連線：網路線、Wi-Fi 連線、網卡停用或 DHCP 沒有回應。用同一個網路上的另一台裝置測試，確認是否只有這台電腦有問題。 |
| **閘道沒有回應** | 已設定預設閘道，但閘道不回應 Ping。問題在這台電腦和路由器之間：連線、Wi-Fi、交換器或路由器本身。確認連線燈號或 Wi-Fi 訊號，以及其他裝置能否連到路由器。 |
| **閘道正常，網際網路不通** | 路由器有回應，但往外的連線失敗。問題在路由器或更外層：WAN 連線、ISP 或上游防火牆。查看路由器的 WAN 狀態，以及其他裝置是否同樣無法上網。 |
| **名稱解析失敗** | 用 IP 直接連線正常，但主機名稱無法解析。問題在 DNS：設定的 DNS 伺服器、過濾服務或名稱本身。把報告中的 DNS 伺服器和公司預期設定比對。 |
| **連線正常但品質不佳** | 連線可用，但封包遺失、延遲、重傳或網卡錯誤超過門檻。常見原因：Wi-Fi 訊號弱、線路壅塞、網路線或連接埠故障。問題發生時再跑一次並比較數字。 |
| **有必要檢查未通過** | 至少一項必要檢查未通過，請看下方失敗的項目。把報告原樣交給 IT。 |
| **部分檢查無法執行** | 沒有發現故障，但部分步驟在這台電腦上無法完成。把報告原樣交給 IT，原因記錄在詳細資料中。 |
| **有需要注意的警告** | 沒有必要檢查失敗，但有檢查提出警告，請看標示的項目。把報告原樣交給 IT。 |

前三種問題標題點名的是你自己就能先看的事：網路線、Wi-Fi 訊號、同一個網路上的另一台裝置是不是也一樣。其餘的交給 IT。另外，只要所有必要檢查都通過，工具就會印出「全部通過」（結語會自己說明這一點：「本次執行的所有必要檢查都通過」，沒有回應的目標寫在下一行）：沒有回應的選用或額外 Ping、TCP、HTTP 目標仍會以「資訊」列留在表格裡（解析不出來的選用 DNS 名稱則是「需注意」），下結論說沒有東西失敗之前，先看那幾列。

### 報告的其他部分

- **電腦與執行資訊**：電腦名稱、使用者、作業系統、工具版本，以及設定檔和報告存放的位置。
- **檢測結果**：每項檢查一列：時間、分類、檢查項目、結果標籤、說明。說明下方的 **顯示詳細資料** 會展開背後的量測值（每一次 Ping 的回覆、網卡的位址、IT 可以自己重做一次的指令）。表格上方的 **全部展開**／**全部收合** 一次打開或關上所有項目。標籤的意思：

  | 標籤 | 意思 |
  |---|---|
  | **正常** | 檢查有執行，結果符合規則 |
  | **需注意** | 檢查有執行，結果沒有違反規則，但值得留意：遺失或延遲超過門檻、計數器達到警告值、關於這次執行本身的提示 |
  | **異常** | 檢查有執行，但結果不符合規則 |
  | **無法檢查** | 這個步驟沒有完成：權限、缺少系統元件、公司政策或執行錯誤。不等同於網路本身一定異常 |
  | **資訊** | 只是記錄、沒有判定的事實：電腦名稱、虛擬網卡、沒有回應的選用 Ping、TCP、HTTP 目標、IT 尚未在設定檔填入公司標準的提示 |

- **IT 診斷資料**：收合在最下面：Wi-Fi 無線細節、路由、閘道的硬體位址、Proxy 設定、traceroute 的前幾跳、網卡驅動程式。這些列是給 IT 看的，永遠不影響整體結果。不打開也沒關係。
- 整體結果下方的六個數字（**正常**、**需注意**、**異常**、**無法檢查**、**資訊**、**合計**）是檢測結果表格的列數統計。

和 HTML 一起寫出的 **TXT** 與 **JSON** 檔記的是同樣的發現：文字檔給沒有瀏覽器的場合讀，JSON 檔給 IT 的工具用，它還多了工具遇到錯誤時的技術細節，其中會寫出程式所在的資料夾。視窗裡的 **開啟 JSON** 會用記事本打開它。

## 5 · 把報告交給 IT

**送哪個檔。** 視窗會在按鈕下方直接寫出來：*把這個檔案交給 IT：…*，那就是 **開啟報告** 打開的那一個，通常是 `.html`。IT 若也要 JSON，**開啟 JSON** 會顯示它，**開啟報告資料夾** 則直接帶你到三個檔案所在的位置。如果 HTML 寫不出來（很少見，視窗會說），開啟報告會改開文字檔或 JSON 檔，那也是報告：送那一個。

**檔案在哪裡。** 按 **開啟報告資料夾**。預設報告放在程式旁邊的 `Reports` 資料夾，也就是 `zh-TW\Reports`，每一輪寫出三個檔案：

```text
NetworkHealthCheck_<日期>_<時間>_<電腦名稱>.html
NetworkHealthCheck_<日期>_<時間>_<電腦名稱>.txt
NetworkHealthCheck_<日期>_<時間>_<電腦名稱>.json
```

IT 可能設定了別的資料夾。若原本的資料夾無法寫入，工具會改存到 Windows 暫存資料夾底下（`%TEMP%\NetworkHealthCheck\Reports`），並在視窗和報告裡說明。按鈕下方顯示的路徑永遠是實際使用的那一個。

**報告資料夾被同步到雲端時。** 新的 Windows 11 預設把桌面、文件和圖片備份到 OneDrive（除非有人關掉），所以套件解壓縮在桌面時，報告是寫進一個會被同步的資料夾：每個檔案一出現就被複製上雲端，不必等你送出，也和工具做了什麼無關。按鈕下方的路徑和報告裡的「報告目錄」那一行會告訴你是哪個資料夾：路徑經過 OneDrive（或公司用的其他同步資料夾）就是這種情況。這不是故障，報告仍然是你的；但報告裡有電腦名稱、你的使用者名稱、各個位址、Wi-Fi 網路，以及下面列出的其他內容，所以公司的規定若不允許這些資料這樣離開電腦，把整個套件移到沒有同步的資料夾再跑一次，或是問 IT。

**原樣送出。** 不要編輯報告。把檔案附在工單或電子郵件裡，或複製到 IT 指定的地方。舊報告是一般檔案，不需要時可以刪除。

**報告裡有什麼。** *身分與這次執行：*電腦名稱、你的使用者名稱、Windows 與 PowerShell 版本及 PowerShell 的語言模式、IT 在設定檔填的單位名稱、執行時間、用的是哪個入口、執行選項（Ping 次數、取樣秒數、traceroute 跳數、哪些選用檢查有跑）與 IT 面板裡輸入的目標，以及設定檔與報告資料夾的路徑，可能含你的使用者資料夾。*每張已連線網卡：*名稱與型號、MAC 與 IP 位址、網路設定檔名稱、閘道、DNS 伺服器、DHCP 模式、連線速度、驅動程式的版本、日期與廠商、流量與錯誤計數，以及旁邊的技術欄位（介面索引、網卡類型、媒體類型、資料來源）。*Wi-Fi：*網路名稱（SSID）、基地台的硬體位址（BSSID）、無線規格、頻段、頻道、速率與訊號。*周圍的網路：*路由器的硬體位址、使用中的路由、Windows 正在使用的 Proxy 設定、IT 設定的公司標準（允許的位址與網段、閘道、DNS 伺服器、預期的 DHCP 模式），以及設定檔警告，警告會引用它反對的值。*測試：*目標的名稱與位址、名稱解析出的位址、網頁請求最後抵達的網址、traceroute 前幾跳的路由器位址、每項測試的結果（回覆、遺失、延遲、連線時間、HTTP 狀態）與有回應的探測所花的時間、整台電腦的 TCP 傳送與重傳計數，以及列上有寫時的檢測方式和可以手動重做的指令。*錯誤：*工具遇到的錯誤內容；JSON 檔還多了錯誤的技術細節，其中會寫出程式所在的資料夾。請依公司對這類資訊的規定處理這個檔案。工具本身絕不會把它上傳到任何地方，只會寫進報告資料夾；除非 IT 把資料夾指到別處，那個資料夾就在這台電腦上；而那個資料夾若正在被同步，Windows 就會從那裡把它複製上雲端，如上所述。

|---|---|---|

| 一列 **啟動提示** 警告：*「原始報告目錄無法寫入，已改存到：…」* | 平常的 `Reports` 資料夾寫不進去，報告改存到那一列寫的資料夾 | 不用修什麼。**開啟報告資料夾** 會開到正確的位置 |
| 訊息方塊 **報告產生失敗**，列出緊急錯誤報告 `NetworkHealthCheck_FATAL_<時間>.txt` | 檢測跑了，但一個報告檔都寫不出來 | 把 FATAL 檔交給 IT，裡面有失敗前檢測找到的一切 |

| 訊息方塊 **檢測無法完成**，列出一個錯誤報告 | 工具遇到無法恢復的錯誤，把它知道的寫下來了 | 送它列出的那個檔案 |
| 整體結果是 **檢測未完整** | 這台電腦上有東西量不到 | 把報告原樣送出，原因在標示 *無法檢查* 的那幾列 |

啟動提示那一列是警告。若它講的是這台電腦——報告資料夾、圖形介面、從 ZIP 裡執行——光是它就會讓整體結果變成 **需要注意**，而網路本身可能還是好的。若它講的是你交給這次執行、卻被丟棄的目標，它不改變結果，而那個目標會在它結果本該出現的地方有自己的一列。不論哪一種，都把那一列讀一下。讀那一列的內容。

## 7 · IT 請你用 IT 入口的時候

`zh-TW` 資料夾裡的 `Start-NetworkCheck-IT.cmd` 開的是同一支工具，上方多了一個 **執行選項（IT）** 面板，而且**不會**自己開始：進度列上方那一行寫著 *就緒，調整選項後按「開始檢測」*。IT 可能請你在 **額外 Ping** 填一個位址、在 **額外 TCP（host:port）** 填主機和連接埠、在 **額外 DNS** 填名稱、在 **額外 URL** 填網址，或改一下 **Ping 次數**、**取樣秒數**，然後按 **開始檢測**。之後打開報告時，每個項目的詳細資料都已經展開。這裡填的東西只對那一次執行有效，永遠不會改到設定檔。**還原設定檔** 會把面板放回設定檔的值。

**那個欄位要的是主機和連接埠一起打。** 標籤上寫著格式 ——「額外 TCP（host:port）」—— 滑鼠移到輸入框上還會出現範例：`8.8.8.8:443`。如果你打的不是主機加連接埠，**開始檢測** 不會開始：欄位會被標記，視窗會說哪裡不對，並給出範例。修正它，或再按一次 **開始檢測**，不帶那個目標直接執行 —— 報告裡會寫這個目標被丟掉，而這則提示不會改變整體結果 —— 被丟掉的目標會在結果本該出現的地方留下一列，讓你看得到哪一項沒有測。

## 9 · 常見的問題

**它會改我電腦上的東西嗎？** 不會。它讀取網路資訊並執行連線測試，不碰 IP、DNS、路由、防火牆、Proxy 或網卡設定，也不安裝任何東西。

**需要系統管理員嗎？** 一般不需要。工具若因為權限不足而讀不到某樣東西，那一列會標示 *無法檢查*，檢測繼續進行。

**報告會被送到哪裡嗎？** 工具不會送。以出廠設定來說，它寫在這台電腦的資料夾裡，除非你送出，否則哪裡都不去；若 IT 把報告資料夾指到網路上的位置，報告就寫在那裡，「電腦與執行資訊」一節會寫出來。不必經人送出就能把報告複製出這台電腦的，是同步服務：新的 Windows 11 把桌面和文件備份到 OneDrive，所以解壓縮在那裡的套件，寫出的報告一出現就上了雲端（第 5 節）。

**它會連到哪些位址？** 以出廠設定來說：你自己的預設閘道、公網位址 `1.1.1.1`（一次 Ping、一次連接埠 443 的連線，以及 traceroute 往它的前三跳）、`https://www.microsoft.com/`（經 Windows 設定的 Proxy 的一次網頁請求，會跟隨網頁給的轉址），加上經這台電腦 DNS 伺服器的 `www.microsoft.com` 名稱查詢。IT 可能已換成公司自己的服務；報告的各列會寫出設定的目標，網頁請求還會寫出最後抵達的網址。

**TCP 重傳那一列寫「無法檢查」。** 計數器讀不到。工具給每次讀取八秒，第一次用完時限會再試一次，因此看到這一列代表兩次都失敗。這個時限是最常見的原因：最容易發生在剛解壓縮出來的資料夾裡第一次執行的時候；權限、政策或壞掉的效能計數器也會讓它讀不到。這不代表有重傳，報告自己也這麼說。有空的話按 **重新檢測**，第二次通常就讀得到；不論讀到與否，都把報告原樣送出。

**TCP 重傳那一列的秒數比 IT 設定的還多。** 那一列會寫出它真正量到的秒數，旁邊附上設定的長度——兩個數字本來就不會一樣，因為取樣是從一次計數器讀取算到下一次，而設定的長度是最短時間、不是目標值。若其中有計數器讀取重試過，那一列還會寫出有幾秒花在失敗的那次嘗試上、以及是哪一次讀取。旁邊的流量數字，就是那一列所寫的那段窗內的計數，不論它多長。

**有一列說 TCP 流量樣本偏少。** 那幾秒量的是這台電腦自己送出的流量，電腦安靜時就沒什麼可量。有三種列會這樣說，意思並不相同：*取樣期間沒有足夠的 TCP 傳送流量*（完全沒送）和 *樣本只有 N 個傳送 segment*（太少，算不出比例）是資訊，不是故障；*流量樣本偏少，但觀察到 N 次重傳* 則是**警告**，而且它正是「警告**不**改變整體結果」的那一種：樣本對所套用的門檻來說太小，所以那一列只報告它看到什麼，把判定留給真正量到的東西。報告底部「IT 診斷」的那些列也一樣不算進整體結果（第 4 節）。樣本小到說不出重傳有多頻繁，但確實有重傳，所以那是對樣本的提醒，不是問題的證據。三種的做法一樣：在使用網路的時候再跑一次，視訊會議中、下載中，或那個會卡的東西正在跑的時候。

**我用 VPN。** VPN 連著的時候，報告會同時列出實體網卡和 VPN 網卡；VPN 那張通常標示為*虛擬*，列為資訊。沒連上或沒有位址的 VPN 網卡完全不會出現。告訴 IT 你跑檢測時 VPN 有沒有連著。

**它說整體正常，但我的問題還在。** 檢測看到的是這台電腦的一個瞬間。問題發生時再跑一次，記下時間，告訴 IT 你當時在做什麼：哪個應用程式、哪台伺服器、其他人有沒有一樣的狀況。

**可以在別台電腦上跑嗎？** 可以，任何 Windows 10 或 Windows 11 的電腦都行。複製整個資料夾。每份報告都會寫出它是在哪台電腦上做的。

**可以改用英文版嗎？** 可以：`Start-English.cmd`，或 `en-US` 資料夾。同一支工具，介面和報告是英文。IT 兩種語言的報告都看得懂。

**舊報告可以刪嗎？** 可以。它們是 `Reports` 資料夾裡的一般檔案。
